# 仓库结构与职责

当前只有四个入口脚本，先沿用可运行的布局。此轮增加文档与实验记录，不迁移既有数据、权重或脚本。

```text
Multimodal-AI4S/
├── README.md                    # 项目入口、运行说明、模型来源
├── DEVELOP.md                   # 当前阶段、待办、阶段日志
├── requirements-baseline.txt    # 当前 baseline 的依赖
├── scripts/                     # 下载、推理和评测入口
├── src/ai4s/                    # 公共模块：当前为实验运行管理
├── configs/                     # 实验入口 JSON 配置
├── tests/                       # 运行隔离与追溯验证
├── experiments/                 # 可追溯的实验记录与索引（小文件）
├── docs/                        # 调研、需求、专题报告、环境快照
├── annotations/                 # 小型标注清单及其说明
├── data/                        # 本地原始数据、下载包、派生样例
├── models/                      # 实际模型权重
├── external/                    # 第三方源码
├── outputs/                     # 每次运行的预测、指标和可视化
└── .venv/                       # 本机 Python 环境
```

## 现有入口

| 脚本 | 职责 |
|---|---|
| `scripts/download_author_data.py` | 下载并校验作者数据包；不是数据标注或训练脚本 |
| `scripts/run_baseline.py` | 图片/视频两级检测，支持采样；没有跨帧跟踪 |
| `scripts/run_manual_roi.py` | 指定容器区域，诊断物态模型表现 |
| `scripts/evaluate_author_data.py` | 固定阈值评估作者标注数据，同时输出真值辅助裁剪诊断 |

当前脚本依赖根目录下 `models/` 和 `external/` 的固定路径，不应直接移动。

## 数据与实验的边界

- `data/` 保存输入及派生数据；按来源设子目录。未来新增数据时记录来源、获取时间、文件校验值、划分、标注版本和适用范围。集群数据登记位置，不在文档中写凭据。
- `annotations/` 保存当前小型 JSON 标注清单。必须区分人工专家真值、助手辅助框和模型预测；当前视频辅助框未获专家物态确认，不能当作正式物态真值。
- `outputs/` 保存机器生成的运行产物；同一次运行一个目录，不覆盖历史结果。
- `experiments/` 保存能解释运行产物的记录。输出被忽略或迁到集群后，仍应能查到实验目的、命令、结果及存储位置。
- `docs/` 保存跨实验的需求、方法说明及总结；`DEVELOP.md` 只维护阶段进度，不堆逐帧预测。

`.gitignore` 已忽略 `data/`、`models/`、`external/`、`outputs/`、`.venv/` 与 Python 缓存。
忽略规则不是备份；重要实验产物需要在有明确存储位置后另行备份。当前未配置自动备份。

## 何时扩展代码结构

当多个实验需要共享预处理、模型接口或指标逻辑时，再提取到 `src/ai4s/`，让 `scripts/` 保留薄入口。
已新增 `configs/` 与 `scripts/run_experiment.py`，统一调度已有入口并记录实验条件；
模型内部固定阈值尚未全部参数化。`tests/` 已覆盖运行器的输出隔离与指纹变化。
后续为坐标映射、指标匹配、时间对齐等公共模块逐步增加测试。
完整边界与实施顺序见[算法架构](算法架构.md)。
