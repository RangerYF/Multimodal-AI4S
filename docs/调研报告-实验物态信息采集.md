## 0. 核心结论

1. **模块定位：采集物体的"状态"，不是"静态信息"。** 纪佳彤（第 3 步）记录谁对什么做了什么（手、器具的位置与运动），本模块记录物体本身怎么了：仪器读数、温度、质量、颜色、浊度、沉淀、结晶、液位等。两者通过同一个物体 ID 和同一条时间线拼成完整的事件。
2. **数据来源按可靠性分四级，优先级依次递减。**
   ① 仪器数字接口直读；② 接触式传感器（PT100/热电偶）；③ 相机读仪器屏幕（OCR）；④ 相机识别容器内容物的物态（CV/VLM）。
   ①② 成本低、精度高，而且能直接充当 ③④ 的 ground truth。
3. **常用仪器基本都能直读，有现成开源驱动，第一周就能拿到数据。**
   - 天平：Mettler MT-SICS、Sartorius SBI、Ohaus 指令集。
   - 加热磁力搅拌器：IKA/Heidolph 的 NAMUR 指令。
   - 温控器：Modbus。
   - 现成驱动：`ika`、`matterlab_hotplates`、PyLabware、`sartoriuslib`、MinimalModbus 等。
   - SiLA 2、OPC UA LADS 这类标准和 TetraScience 这类商业平台，现阶段都**不需要**。
4. **通用 VLM 不能当读数器，也不能单独判断物态。**
   - MeasureBench 真实图上最好成绩约 30%（Gemini‑2.5‑Pro）。
   - ExpVid 指出模型在状态变化追踪上薄弱；MaCBench 实验情境推理只有 0.46。
   - 合理分工：专用 CV 出数值特征，VLM 读结构化特征后做语义判断和兜底。
5. **视觉物态识别已有成熟范式，可以直接复用。**
   - 颜色、动力学：Kineticolor，CIELAB ΔE 方法。
   - 液位、浊度、均一性：UBC Hein 组 HeinSight 1.0–3.0。
   - 物相分割：LabPics、CTG 2.0。
   - **MOF 结晶起始检测**：Farha 与 Aspuru-Guzik 组合作，YOLO 两级检测 clear / cloudy / solid，Chem. Sci. 2026，有开源教程代码。
6. **对"温度传感仪 / 毫米波雷达 / 深度摄像头"三选一的回答：**
   - 温度必上，接触式探头加仪器接口，成本不到 ¥1,000。
   - 热像仪选配，注意它隔着玻璃测不到液体温度。
   - 深度相机上 1 台，只用于人手和人体，透明玻璃器皿会失效。
   - 毫米波雷达在试点阶段不上。
7. **论文贡献点很清楚。** 检索范围内**没有公开数据集同时具备"实验室视频 + 仪器读数时间对齐"**，也没有专门评测"颜色变化、沉淀、结晶、溶解等物态时序变化"的视频 benchmark。本模块的数据正好填补这两个空白，可以作为整个 benchmark 的核心差异点。

## 1. 范围界定与模块接口

### 1.1 与相邻模块的分工

| | 第 3 步（纪佳彤） | **第 4 步（本模块）** | 第 5 步（黄哲睿） |
|-|-|-|-|
| 关注 | 手、容器、器具的位置与运动 | 物体内部状态、仪器读数、环境量 | 综合理解"正在做什么、是否偏差" |
| 输出示例 | "手拿起容器 #3，放到加热台上" | "#3 变浑浊（ΔE=12）""加热台 120.4 ℃""天平 25.03 g 稳定" | "正在加入调制剂，样品顺序与计划不符" |
| 技术路线 | YOLO + ByteTrack | 仪器直读、传感器、OCR、CV、VLM | VLM / LLM |

### 1.2 本模块内容（按优先级）

1. **仪器读数**：天平、加热搅拌器（盘面温度、探头温度、转速）、烘箱、马弗炉、pH 计、离心机等。
2. **温度**：反应液、油浴、加热盘的接触式测温；热像仪看表面温度场。
3. **仪器屏幕 OCR**：针对无法接数字接口的设备。
4. **容器内容物物态**：颜色、浊度/澄清度、液位、分层、沉淀/固体、晶体、气泡/泡沫/凝胶。
5. **标签与身份**：试剂瓶标签、样品编号、二维码/DataMatrix。【建议】这部分从第 5 步移到本模块，用 OCR 加闭集匹配，比让 VLM 看标签更稳。

### 1.3 需要和其他同学约定的接口【建议】

- **共享物体 ID**：第 3 步的跟踪 ID 是物体主键，本模块把状态挂在同一 ID 上。
- **事件触发**：第 3 步检测到"容器放上加热台""加入试剂"等事件时，本模块对该物体启动重点监测，降低常驻计算开销。
- **统一事件格式**（参考 Berkeley A-Lab AlabOS 的设备信号模型）：

```json
{
  "t_host": "2026-11-04T10:23:45.123Z",
  "source": "ika_rct_01 | balance_01 | cam_closeup_02 | thermal_01",
  "object_id": "vessel_3 | null",
  "signal": "plate_temp | mass | delta_E | turbidity | phase_label | ...",
  "value": 120.4,
  "unit": "degC",
  "status": "stable | dynamic | unreadable",
  "confidence": 0.97,
  "evidence": {"video": "cam_closeup_02", "frame": 18342}
}
```

- **时间同步**：仪器数据大多从本模块产生，统一时钟方案应由本模块牵头（见第 6 节）。

## 2. 路线一：仪器数字直读（最高优先级）

### 2.1 常见协议与开源驱动

| 仪器 | 协议要点 | 开源驱动 / 参考 |
|-|-|-|
| **Mettler Toledo 天平** | MT-SICS ASCII 指令：`S` 读稳定值，`SI` 立即读数，`SIR` 连续输出，`Z` 清零，`T` 去皮。返回 `S S 25.03 g` 表示稳定，`S D` 表示动态。接口有 RS232、USB 虚拟串口、Ethernet | [mettler_toledo_device_python](https://github.com/janelia-python/mettler_toledo_device_python)（Py3 需要先测试）；[labmcp-mettler-toledo](https://pypi.org/project/labmcp-mettler-toledo/)；XPR 系列可用 [matterlab_balances](https://pypi.org/project/matterlab-balances/)（Web Service）；[MT-SICS 手册](https://www.mt.com/dam/P5/labtec/17_Miscellaneous/RM_Advanced_and_Standard_Level_Balances_SICS_EN.pdf) |
| **Sartorius 天平** | SBI（ESC 开头的 ASCII，出厂默认）或 xBPI（二进制） | [sartoriuslib](https://github.com/GraysonBellamy/sartoriuslib)（异步，自动识别协议，Python 3.13+） |
| **Ohaus 天平** | `IP` 立即打印，`SP` 稳定后打印，`CP` 连续打印；9600 8N1 | 没有专用库，pyserial 十几行即可。[手册](https://dmx.ohaus.com/WorkArea/downloadasset.aspx?id=28020) |
| **IKA 加热搅拌器**（RCT digital、C-MAG HS 等） | NAMUR 指令，9600 7E1，设备只应答不主动推送。`IN_PV_1` 外接探头温度，`IN_PV_2` 盘面温度，`IN_PV_4` 转速，`IN_SP_x` 设定值；带 Watchdog。部分 basic 型号没有接口 | [`ika`](https://pypi.org/project/ika/)（Hein 组维护）；[手册](https://pimcore.imlab.eu/Bestanden/Ika/ika-rct-digital-magnetische-roerder-handleiding-en.pdf) |
| **Heidolph** | 只有 Hei-Connect 型号带 RS232，需要先发 `PA_NEW` 切到扩展协议 | [matterlab_hotplates](https://pypi.org/project/matterlab-hotplates/)（统一接口覆盖 IKA 和 Heidolph） |
| **pH 计**（Mettler SevenExcellence 等） | RS232 设为"Compact Printer"模式，抓取文本输出；没有公开 SDK | pyserial 自写 |
| **工业温控器 / 马弗炉**（Eurotherm 等） | Modbus RTU（RS485），寄存器地址因型号而异 | [MinimalModbus](https://minimalmodbus.readthedocs.io/en/stable/usage.html) |
| **普通恒温烘箱**（MOF 溶剂热常用） | 很多没有接口，Memmert 等协议未核实 | 【建议】外挂热电偶记录仪，见 4.2 节 |

**通用框架**：[PyLabware](https://github.com/croningp/pylabware)（Cronin 组，统一化学硬件接口，带仿真模式）；[LabMCP](https://github.com/K-Dense-AI/lab-instrument-mcps)（为 LLM agent 准备的 MCP server，含仿真器、安全限值、审计日志，后续做 agent 演示可以用）。

### 2.2 标准与商业平台：现阶段不建议投入

| 名称 | 结论 |
|-|-|
| SiLA 2（gRPC 设备控制标准） | 常见天平和加热台没有原生支持，自己包一层对"拿数据"没有帮助。论文可作为"可对接"的加分点 |
| OPC UA LADS（2023 发布） | 现役学术设备几乎都不支持，只参考它的数据模型层级 |
| Allotrope ASM | **值得参考字段与单位命名（QUDT）**，让数据 schema 与标准对齐；开源转换工具 [allotropy](https://github.com/Benchling-Open-Source/allotropy) |
| AnIML | 长期停留在草案阶段，了解即可 |
| TetraScience / Scitara DLX / Benchling Connect | 面向药企；Scitara 每台仪器每年约 $2,000（[AWS 报价](https://aws.amazon.com/marketplace/pp/prodview-vvqv7gxgeehbm)），不适合本项目 |
| LabTwin（语音实验助手） | 2024 年并入 labforward，据二手来源已停止服务（未核实）。它是"语音 + 实验记录"的重要先例，**related work 应引用** |
| Elemental Machines | IoT 环境/设备监测，15 秒一个点，粒度太粗 |

### 2.3 自驱动实验室怎么记录设备数据（可借鉴）

- **Berkeley A-Lab / AlabOS**：用 `@log_device_signal` 装饰器定期把设备信号（如炉温）带时间戳写入 MongoDB（[文档](https://alab-management.readthedocs.io/en/latest/alab_management.device_view.device.html)）。**和本模块需求最接近的范式。**
- **Cooper 组 ARChemist**：基于 ROS，消息自带时间戳，过程状态存 MongoDB（[论文](https://pubs.rsc.org/dd/article/5/3/1363/1230091/A-mobile-robotic-process-chemist)）。
- **Cronin 组 SensorHub**：Arduino 定制板接颜色、pH、温度、电导等低成本传感器，经以太网接入（[Nat. Commun. 2024](https://www.nature.com/articles/s41467-024-45444-3)）。
- **Hein 组 IvoryOS**：每台设备一个 Python 包，提供统一 API（[Nat. Commun. 2025](https://www.nature.com/articles/s41467-025-60514-w)）。

**和这些工作的区别**：它们面向机器人操作，本项目面向**人工操作**，而且要求**多模态同步**、**以仪器真值作为视觉任务的监督信号**。这可以写成论文的差异化叙述。

## 3. 路线二：相机读取仪器屏幕与标签

只在仪器无法直读时使用。它同时可以做成 benchmark 的子任务，因为直读数据天然提供真值。

### 3.1 现状

**数码管 / 七段 LCD：通用 OCR 零样本不可靠**
- PaddleOCR 官方教程承认小数点、负号容易漏。用 DS-Digital 字体合成数据微调后，SVTR_Tiny 准确率从 52% 提到 78.9%（[教程](https://github.com/PaddlePaddle/PaddleOCR/blob/release/2.7/applications/%E5%85%89%E5%8A%9F%E7%8E%87%E8%AE%A1%E6%95%B0%E7%A0%81%E7%AE%A1%E5%AD%97%E7%AC%A6%E8%AF%86%E5%88%AB/%E5%85%89%E5%8A%9F%E7%8E%87%E8%AE%A1%E6%95%B0%E7%A0%81%E7%AE%A1%E5%AD%97%E7%AC%A6%E8%AF%86%E5%88%AB.md)）。
- 一个 48 张图的小基准里，PP-OCRv5 原图整串精确匹配只有 22.92%（[repo](https://github.com/chandrika-kantipudi/seven-segment-ocr-benchmark)）。
- 机位固定时，[ssocr](https://www.unix-ag.uni-kl.de/~auerswal/ssocr/) 或"段中心像素亮度查表"就很有效。
- 抄表数据集（UFPR-AMR、Copel-AMR）是电表、水表，字体和布局与实验仪器差别大，只能用来预训练。

**指针表**
- 主流做法是"检测 → 关键点 → 角度插值"，或者"关键点 + OCR 读刻度"。
- 代表工作：WACV 2024 Leon-Alcazar 等、ICRA 2024 "Under pressure"（误差小于 2% 量程）。
- 合成数据集 [SyncG](https://github.com/SKYWOWDYH/SyncG)（Sci. Data 2026，20k 张）。

**VLM 读表**
- [MeasureBench](https://arxiv.org/abs/2510.26865)（CVPR 2026）：真实图最好约 30%。单位识别超过 90%，主要错在指针和刻度定位。
- InSituMeasure 发现模型对不可读的表也会自信地给出数值。
- [CAD2DMD-SET/DMDBench](https://arxiv.org/abs/2508.21732) 面向万用表、体温计等数显设备，LoRA 微调后提升明显，**和实验室数显仪器最接近，值得参考。**
- 化学场景：[MaCBench](https://www.nature.com/articles/s43588-025-00836-3) 设备识别 0.77，实验情境推理 0.46。

**标签**
- 能贴码就贴码：DataMatrix/QR，用 `zxing-cpp` 解码；BioVL-QR 已经在生物实验中用 Micro QR 标物体。
- 曲面 OCR 和手写管标都不成熟。【建议】商业试剂瓶 OCR 出品名后，模糊匹配实验室试剂清单（闭集）；自制样品管推行预打印 DataMatrix 标签。

### 3.2 推荐流程

1. **ROI 注册**：固定机位标定一次；第一视角用 YOLO 检测屏幕再做单应矫正。
2. **变化触发**：ROI 帧差，连续稳定约 0.3–0.5 s 再识别，避开过渡帧；手部遮挡时暂停。
3. **分类型识别**：七段屏用 ssocr 或段亮度，备路用微调的 SVTR/PARSeq；指针表用关键点；标签先走条码，解不出再走 OCR。
4. **时序校验**：多帧投票，格式正则（位数、小数位、单位），物理约束（温度变化率上限、天平稳定标志）；置信度低时输出"不可读"，不强行给值。
5. **VLM 只做仲裁**：输入 ROI 裁剪图和候选读数，判断"是否可读、单位、哪个候选更合理"。
6. **拍摄工程**：相机略离轴，配漫射侧光和遮光罩；必要时加 CPL 偏振镜，但要注意 LCD 本身是偏振光，需要对着画面调角度；LED 数码管要降低曝光，减轻光晕。

## 4. 路线三：容器内容物物态的视觉识别

### 4.1 学术与工业现状

**数据集基座**
- [Vector-LabPics](https://pubs.acs.org/doi/10.1021/acscentsci.0c00460)（ACS Cent. Sci. 2020，2,187 张）和 [LabPics 2](https://www.cs.toronto.edu/chemselfies/)（约 7,900 张）。类别有 liquid / solid / foam / suspension / powder / gel / granular / vapor，另有容器、标签、物质间关系。
- [TransProteus](https://arxiv.org/abs/2109.07577)：5 万张 CGI 加真实深度图，可估计液体 3D 体积。
- [CTG 2.0](https://arxiv.org/abs/2603.10782)（2026）：3,668 张，23 类玻璃器皿，5 种相界面，AP@0.5 = 84.4%；可输出界面高度和相分数，带有色/无色属性头。

**受控工位下的反应监控（成熟度高）**
- **HeinSight（UBC Hein 组）**
  - 1.0：ROI 边缘检测监测液位。
  - [2.0](https://pmc.ncbi.nlm.nih.gov/articles/PMC10806693/)（Chem. Sci. 2024，与 Pfizer 合作）：固体残留、液位、均一性、浊度、颜色，用于结晶的闭环控制。
  - [3.0](https://www.cell.com/device/fulltext/S2666-9986(24)00240-0)（Device 2024）：YOLO，12 瓶并行，相界面清晰度。
- [**YOLO-text**](https://pubs.rsc.org/en/content/articlelanding/2026/dd/d5dd00346f)（Digital Discovery 2026）：用 LLM 读实验方案，推断当前阶段可能出现的类别，作为检测上下文，mAP 提升 4.8–7%。**正好解决"外观相似、要靠上下文判别"的物态**，和本项目有实验方案上下文的条件高度契合。
- **Kineticolor（Strathclyde Reid 组）**
  - 方法：ROI 平均颜色转为 RGB/HSV/CIELAB 共 12 个参数，核心指标是相对首帧的 ΔE，可把视频变成动力学曲线（[OPRD 2022](https://strathprints.strath.ac.uk/83278/1/Barrington_etal_OPRD_2022_Computer_vision_for_kinetic_analysis_of_lab.pdf)、[ACIE 2025 并行 HTE](https://onlinelibrary.wiley.com/doi/full/10.1002/anie.202413395)）。
  - 拍摄规范上的关键发现（[Anal. Bioanal. Chem. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12528221/)）：斜视角会让 ΔE 偏差最多增大 64%；色卡矩阵校正可把跨设备和光照差异降低 65–70%；超出 sRGB 色域会产生假性曲线。
- **滴定 / 溶解**：HSV 阈值判滴定终点（J. Chem. Educ.）；Hein 组用浊度判断"完全溶解"做溶解度筛选（[iScience 2021](https://www.cell.com/iscience/fulltext/S2589-0042(21)00144-9)）。

**结晶与 MOF（和 Yaghi 场景最贴近）**
- [**Farha + Aspuru-Guzik，Chem. Sci. 2026**](https://pmc.ncbi.nlm.nih.gov/articles/PMC13308677/)：高通量平台按时间拍样品瓶，YOLO 两级检测（先定位样品瓶，再检测 clear liquid / cloudy liquid / solid），超过 13,000 张时序图，自动识别稀土 MOF 结晶起始与动力学。
  - 配套教程与代码：[CV-HTE-Tutorial](https://github.com/ac-rad/CV-HTE-Tutorial/)。**建议作为第一个复现的 baseline。**
- [UW Shijing Sun 组](https://chemrxiv.org/doi/full/10.26434/chemrxiv-2025-nq31g)（J. Mater. Chem. A 2025）：Co-MOF-74 显微图像中单晶与团簇的自动计数，比人工快约 35 倍。
- Cronin 组 [crystal explorer](https://arxiv.org/abs/2409.05196)：瓶底相机配 Mask R-CNN，区分无定形、粉末、团簇、单晶和多晶型。
- [MARCO](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC6010233/)（蛋白结晶，49 万张）：四分类 Crystals / Precipitate / Clear / Other，**可以借作结晶结果标签体系的起点。**
- COF 方向没有检索到基于相机的物态检测，结晶度依赖 PXRD。Yaghi 组本身也没有检索到视觉物态工作（不代表不存在）。

**自驱动实验室中的视觉 / VLM**
- Cooper 组 [LIRA](https://www.nature.com/articles/s42004-025-01770-1)：微调 VLM 检查工作流状态。
- [Chemist Eye](https://arxiv.org/html/2508.05148)：VLM 加 YOLO 监测 PPE；长波红外站监测热板火情。

**VLM 物态评测**
- MaCBench、[ExpVid](https://arxiv.org/abs/2510.11606)（ICLR 2026，细粒度感知最高约 60%，混淆外观相似的材料）、[SciVideoBench](https://scivideobench.github.io/)（闭源平均 38.8%）、LabSafety Bench、LabShield。
- **没有检索到专门评测真实实验视频中颜色变化、沉淀、结晶、溶解等物态的 benchmark。**

### 4.2 各类物态的技术难度（结合 MOF/COF 场景）

| 难度 | 物态 / 现象 | 推荐方法 | 前提 |
|-|-|-|-|
| **A. 简单 CV 即可** | 颜色变化（金属盐与配体混合、活化变色）、浊度/澄清度、固定机位液位、指示剂终点、热板/烘箱附近温度异常 | ROI + CIELAB ΔE / 浊度 / 边缘检测 + 时序阈值；红外 + dT/dt 规则 | 固定机位、黑背景或底光、画面内放色卡、ROI 已知 |
| **B. 需要学习模型** | 移动视角下的容器与内容物分割、沉淀/固体出现、离心后的沉淀与上清、相界面与分层（洗涤、溶剂交换）、晶体形貌、气泡/泡沫/凝胶 | YOLO / Mask R-CNN / CTG 类相界面模型；在 LabPics 上预训练，再用自采数据微调；晶体形貌需要微距或显微 | 有一定量的自标注数据 |
| **C. 需要 VLM 与上下文** | 悬浊液与乳浊液、"未完全溶解"与"析出"等外观相似的物态；视觉变化与操作语义对齐；异常与安全判断；教学中的错误识别 | VLM 读取 A、B 两级的结构化特征（ΔE 曲线、相分数、mask 面积），再结合实验方案或语音上下文推理（YOLO-text、LIRA 思路）；不确定时交人工复核 | 现有 benchmark 显示 VLM 在这一级仍不可靠 |

**MOF/COF 的特殊难点（领域推断，需要和课题组确认）**
- 溶剂热反应在密闭瓶内、烘箱里进行，过程本身拍不到，只能抓"进烘箱前"和"出烘箱后"的关键帧；烘箱温度曲线只能靠传感器。
- COF 和许多 MOF 产物是不透明粉末，结晶度目视无法判断，需要和 PXRD 等表征结果关联。这可以设计成"目视判断与仪器表征一致性"任务。
- 活化（溶剂交换、真空加热）可能伴随颜色变化，适合用 ΔE 记录，但要逐个体系建立标签。

### 4.3 物态子模块的分层流水线【建议】

```
采集层   固定特写相机(黑背景+底光+色卡) / 第一视角 / 热像 / 传感器 / 仪器直读
   ↓
容器层   容器检测与跟踪（复用第 3 步的 ID）+ 标签/二维码 → 物体身份
   ↓
内容物层 物相分割（类别参考 LabPics + Farha：clear / cloudy / suspension /
         solid-precipitate / crystal / powder / foam / gel / residue / empty）+ 液位/相界面
   ↓
特征层   逐帧 ΔE、hue、浊度、相分数、固体面积、液位；T(t)、dT/dt；仪器读数序列
   ↓
事件层   变化点检测 → "颜色变化""浑浊出现""沉淀出现""溶解完成""分层"
         "液位下降""升温到设定值""温升异常""称量完成"
   ↓
语义层   VLM/LLM：关键帧 + 结构化特征 + 实验方案/语音 → 物态描述、是否符合预期
   ↓
输出     统一事件格式 → 实验时间线（供第 5、7、8 步使用）
```

## 5. 传感器选型

### 5.1 回答"温度传感仪？毫米波雷达？深度摄像头？"

| 传感器 | 结论 | 理由 |
|-|-|-|
| **接触式温度**（PT100/热电偶）+ 仪器接口 | **必上，优先级最高** | 温度和时间是 MOF/COF 合成（溶剂热、回流、油浴、活化）的核心状态变量。成本不到 ¥1,000，能得到精确的 ground truth 曲线，可以直接标注"加热中 / 到达设定温度 / 降温"等状态 |
| **热像仪**（LWIR） | **选配 1 台** | 看加热盘、油浴表面、外壁的温度场，以及"徒手拿热烧杯"这类安全事件，而且对人脸隐私友好。**玻璃对长波红外不透明，它测到的是瓶壁温度，不是液体温度**，还有反射伪影 |
| **深度相机** | **上 1 台，只用于人** | 对手-物交互、操作姿态、台面三维布局有价值；**透明玻璃器皿会出现深度缺失或错误**（ClearGrasp 已有充分演示），不能用来测液面 |
| **毫米波雷达** | **试点阶段不上** | 擅长人员存在、呼吸心率、大罐液位。点云稀疏，识别不了手指级操作；台面金属多，多径反射严重；小玻璃器皿液位在实验室里没有可靠案例；TI 例程部分不开源，集成成本高。以后有"无摄像头隐私模式"或通风橱人员监测需求时再单独评估 |

### 5.2 具体型号参考（价格为检索时零售价，需复核）

**热像仪**

| 型号 | 规格 | 价格 | 接口 |
|-|-|-|-|
| Topdon TC001 / InfiRay P2 Pro | 256×192，25 Hz | 约 $200–300（约 ¥1,400–2,100） | Linux 下取原始温度数据靠社区方案，未核实 |
| FLIR Lepton 3.5 + PureThermal | 160×120，8.7 Hz，辐射测温 | 约 $370 | UVC，生态最好 |
| Seek Mosaic Core | 320×240 | $599–699 | 官方 SDK，需要严肃测温时选 |

**接触测温**

- MAX31856 + K 型热电偶：高温场景，$17.50 + 探头。

## 6. 时间同步与录制基础设施

### 6.1 主流数据集的做法

| 数据集 | 同步方式 | 精度 |
|-|-|-|
| Ego-Exo4D | 手机播放 **QR 码时间码视频**，每台相机开录后拍一下；没用时间码硬件，整套设备约 $3,000 | GoPro 与 Aria 相差 ≤1 帧（±16.7 ms） |
| HoloAssist | Microsoft \psi 框架统一打时间戳 | — |
| CaptainCook4D | 论文自述 GoPro 与 HoloLens 之间**不同步** | 反面教材 |

### 6.2 推荐方案【建议】

1. **系统时钟**：所有采集机用 chrony 同步到局域网 NTP 服务器（毫秒级）。化学操作的时间尺度是百毫秒到分钟，**不需要 PTP 或硬件同步线**。
2. **中间件**：用 [Lab Streaming Layer（LSL）](https://pmc.ncbi.nlm.nih.gov/articles/PMC12434378/)，它会持续测量各机器之间的时钟偏移，LabRecorder 把所有流写入单个 XDF 文件。
   - 仪器、传感器数据直接作为 LSL 流。
   - **视频在本地编码保存，只把帧号和时间戳推到 LSL**，避免占满带宽。
   - 用 pyxdf 加载时要**关闭对视频流的 dejitter**。
3. **视觉和音频锚点**：每个实验开始、结束、中途各扫一次 QR 时间码，同时拍手或蜂鸣。实验常常持续 1–3 小时，单靠一次对齐会被漂移拖垮。GoPro 自带的时间码同步开机 60–90 分钟后也会漂移。
4. **仪器轮询**：1–2 Hz 主动轮询，记录请求和响应两个时刻以估计延迟；保留设备原始回包和稳定标志。
5. **备选**：团队有 ROS 经验时，可以用 ROS 2 Jazzy + rosbag2（MCAP 格式）+ Foxglove。
6. **论文里应报告同步误差**：拍一个 LED 闪烁，同时在日志里打标，测量各个流之间的偏差。

### 6.3 数据量与算力

- 1 路第一视角 + 3 路固定机位（H.265）+ 1 路深度 + 1 路热像，约 **100–200 GB/小时**。一个学期每个工位 2–4 TB，需要 NAS。
- **Jetson Orin Nano 没有硬件编码器（NVENC），不适合做多路录制主机。** 推荐一台 x86 工作站加 RTX 显卡：编码有余量，还能在线跑打码和 VLM 推理。
- 每台 USB3 相机尽量独占一个 USB 控制器。

## 8. 前期科研探索计划（建议 8 周）

### 8.1 待验证的研究问题

| 编号 | 问题 | 判定标准（初拟） |
|-|-|-|
| **Q1** | 培训会用到的仪器里，能数字直读的比例是多少？ | 覆盖率 ≥70% 时，以直读为主干 |
| **Q2** | 固定机位下，屏幕 OCR 相对仪器真值的精度能到多少？ | 整串精确匹配 ≥95% 才能进主流程，否则只做 benchmark |

## 9. 风险与合规

| 风险 | 应对 |
|-|-|
| 部分仪器无接口或型号老旧 | 外挂传感器 + OCR 兜底；在 P0 阶段就量化覆盖率 |
| 溶剂热过程不可见 | 以烘箱温度曲线加前后关键帧为主，不追求过程视频 |
| 物态标注主观、一致性差 | 标签体系从成熟方案起步；多人标注计算一致性（κ）；尽量用仪器数据锚定 |
| 实验室光照与反光多变 | 固定工位标准化（黑背景、色卡、遮光）；第一视角数据只用于 B、C 级任务 |
| 跨场景泛化差（CHiMP 显示 MARCO 跨设备会掉点） | 论文中设置跨工位、跨实验的划分 |
