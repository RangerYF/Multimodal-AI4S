# 算法探索架构

## 设计目标

支持离线视频与作者数据的可复现实验，逐步接入摄像头和仪器。
把不同算法的输入输出、评测和运行记录分开，使更换模型不必重写数据采集与报告。
当前采用单仓库、离线批处理；暂不引入微服务、消息队列或在线训练平台。

## 模块边界

```text
视频/相机 ── 帧与时间戳 ── 容器定位/指定 ROI ── 物态识别 ─┐
仪器接口 ─────────────────── 数值采集 ───────────────────┼─ 观测记录
仪器屏幕 ── 屏幕定位 ── OCR/单位与有效性校验 ────────────┘
观测记录 ── 对象关联与时间对齐 ── 时序事件 ── 证据与解释
                     ↑ 各阶段分别评测，实验运行器统一记录 ↑
```

| 层 | 负责什么 | 适合探索的变量 | 当前状态 |
|---|---|---|---|
| 数据与采集 | 视频解码、采样、传感器读数、数据划分 | 拍摄条件、采样频率、数据质量 | 已有离线视频读取；仪器待接入 |
| 定位与区域 | 找容器、裁剪、坐标转换 | YOLO、固定 ROI、后续跟踪 | 已有 YOLOv5 与指定 ROI |
| 单时刻状态 | 输出区域类别/置信度或数值/单位 | 现有 YOLOv8、其他检测/分割方法、OCR | 仅五类物态模型已实现 |
| 对象与时间 | 容器持续身份、时钟对齐、缺失处理 | 跟踪、时间同步与质量筛选 | 未实现；当前 vial_index 仅帧内编号 |
| 时序事件 | 根据连续观测判断变化 | 连续帧确认、平滑、状态机、时序模型 | 未实现 |
| 解释与展示 | 引用观测证据，关联实验上下文 | 规则说明、后续多模态解释 | 未实现；视觉固体不证明化学结构 |
| 评测与运行管理 | 固定协议、对照实验、产物追溯 | 状态指标、事件指标、成本 | 已有框评测和本轮实验运行器 |

## 接口约定（待按模块逐步实现）

统一观测建议包含 `schema_version`、`experiment_id`、`sample_id`、`object_id`、
`timestamp`、`time_basis`、`source`、`quantity`、`value`、`unit`、`quality`、`evidence`。
视觉观测另外带类别、框、坐标系和置信度；仪器观测保留原始读数及稳定/去皮状态。
尚未关联的对象 ID 可为空；未知状态不转成“无固体”，缺失读数不填零。
时间必须注明相对视频时间或设备/UTC 时间，未同步时不可直接融合。

事件输出单独包含对象、事件类型、前后状态、时间区间及证据记录 ID。
采样只能约束变化发生区间，不应把第一张检出帧当作精确反应起点。
现有预测 JSONL 保留原格式；待新增模块时用适配器转换，不伪称现有脚本已遵循新协议。

## 代码组织与实施顺序

当前已建立 `src/ai4s/experiments.py` 公共运行层，`scripts/run_experiment.py` 是命令入口，
`configs/` 保存 JSON 配置，`tests/` 验证运行隔离和输入追溯。
已有模型脚本继续可独立执行。模型阈值仍在原脚本中固定，本轮没有改变检测算法或指标。

后续按实际实验需要逐项提取公共模块：

1. `ai4s/vision/`：先封装现有两级模型，再复用到视频和作者数据评测；用相同输入做回归比较。
2. `ai4s/data/` 与 `ai4s/evaluation/`：统一数据读取、分组划分、框指标和错误分析；测试匹配及坐标映射。
3. `ai4s/temporal/`：在有事件真值后实现状态确认与事件指标。
4. `ai4s/acquisition/` 与观测协议：获得仪器接口条件后接入数值，再做跨模态时间对齐。

以上四项为计划，不预建空模块。算法实现与实验记录分离：代码在 src/scripts，结论在 experiments/docs。

## 运行一个可追溯实验

从仓库根目录执行，先复制配置并更改唯一的 `run_id`：

```powershell
.\.venv\Scripts\python.exe scripts/run_experiment.py configs/author-eval.json --dry-run
.\.venv\Scripts\python.exe scripts/run_experiment.py configs/author-eval.json
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

支持任务 `video`、`author_eval`、`manual_roi`，分别调用已有三个脚本。
`args` 是该脚本原有参数列表；不允许指定 `--output`，输出由 ID 管理。
`inputs` 要列出全部实际输入，包括 ROI 清单引用的视频；运行器对声明的文件逐一做 SHA-256。
它不会自动发现遗漏的间接输入，配置作者需要核对。大数据目录首次指纹计算会较慢。
`--dry-run` 检查配置、输入是否存在及输出冲突，打印命令，不加载模型，也不保证环境可运行。

输出结构：

```text
outputs/<run_id>/
  config.json          # 实际运行配置
  run.json             # 状态、命令、Git 提交/脏状态、时间、第三方提交
  inputs.json          # 声明的数据输入指纹
  weights.json         # 两个现有模型的权重指纹
  environment.txt      # 当前解释器 pip freeze
  source/              # scripts/src 的实际 Python 源码快照
  console.log          # 子进程日志
  artifacts/           # 原入口生成的预测、指标及可视化
```

运行失败标记为 failed，日志和已有产物保留；复跑必须换 ID。completed 仅代表进程成功结束，
不代表算法有效。环境快照不是独立安装包，上游本地修改也未完整归档；正式对照应保持上游源码不变。

## 评测约定

先按实验/样品分组固定数据划分，再做参数选择；最终测试集不参与选择阈值。
状态评测保留框级 PR/F1 和类别存在性，事件评测另统计漏报、误报及时间偏差。
人工指定 ROI 与真值辅助裁剪必须标为诊断，不与可部署自动流程混淆。
每次对照明确变化因素，连同失败样例写入实验记录；历史作者集结果不因后续架构改造覆盖。

## Git 工作方式

主分支 `main` 保存可运行基线；新探索用 `exp/<主题>`，基础代码改动用 `feat/<主题>`。
实验前尽量提交代码和配置，实验后提交记录与小型结果摘要。数据、权重、环境、运行产物留在外部存储，
由路径和指纹关联。Git 不代替原始数据备份。
本轮只建立本地仓库；远程地址与托管平台尚未指定，不进行上传。
